Adaptive Cold-Start Predictor for AWS Lambda

Forecast load from per-minute invocation history, then pre-warm Lambda containers only when a spike is expected. Source code and README on GitHub

How it works

  1. Count. The target Lambda writes an atomic per-minute counter to DynamoDB and records whether each request was a cold start.
  2. Forecast. Every minute, EventBridge triggers the predictor Lambda. It reads the last 15 minutes and evaluates a gradient-boosting model (150 trees, exported to JSON) to forecast requests two minutes ahead.
  3. Pre-warm. If the forecast crosses a threshold, the predictor sends parallel warm-up pings, which makes Lambda create that many containers before the spike arrives.
  4. Measure. A benchmark compares three strategies: no warming, fixed-interval warming, and predictive warming.

What this does and does not show

  • Both warming strategies removed cold starts in this workload; predictive warming used 33% fewer pings than fixed-interval warming.
  • The model was trained on simulated, periodic traffic, so it largely learns the schedule. Try Inject unscheduled burst: the forecast does not anticipate it, and the burst finds cold containers.
  • Try idle traffic with the predictive strategy: with no recent spikes the model stays quiet instead of warming on the clock alone.
  • Each strategy was benchmarked once; the fixed baseline’s interval and pool size are my own choices.
